          配置与 MCP 使用指南
          
项目说明

          
SSH 工作台在本机管理机器、凭证和权限，通过 MCP 让 Codex 连接机器、执行运维任务、传输文件，也支持按分组批量操作。先在管理页配好机器，再在已接入本项目 MCP 的 Codex 对话中描述任务。

        

        
    
          
  1. 配置连接按连接方式选择私钥、Plink 或 Tailscale；不是每一项都要配置。
    2. 
          
  2. 添加机器填写 IP、账号、系统及所属分组，设置权限，保存后检测连接。
    3. 
          
  3. 交给 Codex打开左侧机器的 MCP 开关，告诉 Codex 要操作哪台机器或哪个分组。
    4. 
        

        

          
分组批量操作
可以直接这样对 Codex 说

          

            
A 组资源巡检
“检查 A 组所有机器的 CPU 占用，汇总平均值，按占用从高到低列出，并单独说明连接失败或权限不足的机器。”
先在左侧新建 A 组，用机器卡片的移动按钮分配成员。机器需选用「基础巡检」预设或完全访问；平均值只统计成功采样。
ssh_list_groups → ssh_group_cpu({"group":"A组"})

            
B 组安装 Docker
“检查 B 组机器的系统和 Docker 状态，跳过已经安装的机器。先给我安装方案，确认后批量安装，并逐台汇报结果。”
安装需要远端账号具备相应权限，以及机器允许执行安装命令；任意安装脚本需完全访问。混合系统要分别提供对应脚本，长任务可查询进度、跟随日志和取消。
ssh_group_start → ssh_group_status；逐台日志使用 ssh_tail。

          

          
组控按任务开始时选中的机器执行，逐台检查权限并返回结果；分组不会额外授予权限。失败或取消不会自动撤销已经完成的远端操作。

        

        

          
各项配置有什么用
            

              

                
私钥管理
导入或生成本机 SSH 私钥，多台 OpenSSH 机器可复用同一把。机器页下拉选择；首次连接把对应公钥写入远端账号，私钥留在本机。

                
PuTTY 共享连接
填写本机 plink.exe 路径，用于 AccessClient 堡垒机连接。先在 AccessClient 打开并登录目标 PuTTY 会话，再检测连接；需要匹配会话时按机器页提示重新打开。保持该会话可用，工具会复用连接执行任务。

                
Tailscale SSH
填写已安装的 Tailscale 程序路径。本机需登录 Tailnet，远端需启用 Tailscale SSH 并获网络策略授权；远端支持 Linux、macOS。此连接方式当前不提供文件传输。

                
机器 IP、说明、分组
IP 是实际连接地址；说明用来区分机器用途；分组用于整理列表和批量任务。默认分组不可删除，机器上的 MCP 开关控制该目标是否可被调用。

                
系统、账号、端口
系统决定脚本及巡检指令格式；账号决定远端操作身份；SSH 端口通常为 22，可按实际服务修改。完全访问也不会自动获得远端管理员权限。

                
known_hosts
保存已信任的服务器主机密钥，用于确认连接的是正确服务器；它与用于登录的用户公钥不同。首次连接应核对服务器指纹。

                
命令与传输上限
命令最长时间与文件传输最长时间分别设置。使用后台任务不会绕过上限；构建和大文件任务应提前设置足够时长。

                
文件传输目录
受限传输要配置允许方向、本机目录和远端目录；上传、下载及同步均受这些权限限制。完全访问开放任意绝对路径，预设命令模式不开放文件传输。

              

            

          

          
权限模式与 4 组内置预设
            

              
在每台机器的「权限管理」中选择。预设命令组执行固定巡检操作；白名单只放行已配置的命令；完全访问允许任意命令及文件操作；禁止访问不授予运维执行权限。

              
基础巡检
固定模板读取系统、CPU、内存、磁盘、进程与端口摘要，限制执行时间和输出。
日志排查
按机器授权的精确文件路径或服务读取有限日志，不允许任意路径和脚本。
Docker 只读巡检
查看容器列表、状态、资源、健康和有限日志，不提供容器内命令执行。
Docker 保护
自身不授予操作，可与受限巡检预设组合；关闭任意执行与文件传输入口，禁止 Docker 启停、重建和删除等变更。不能作为完全访问模式下的额外黑名单。

              
Codex 先调用 ssh_list_allowed_operations 查看允许的操作及参数，再用 ssh_run_operation 执行。模板不可编辑；预设只约束本工具，不限制其他 SSH 登录会话。

            

          

          
MCP 提供哪些服务、怎么调用 · 24 个工具
            

              
通常直接向 Codex 描述需求即可。工具中的 target 使用 ssh_list_targets 返回的机器 ID 或别名，不需要向对话粘贴私钥。

              
服务MCP 工具使用方式

              
服务与连接ssh_gateway_status · ssh_ping
ssh_open_admin · ssh_list_targets
ssh_check_connection		“列出可用机器，检查这台机器能否连接。”网关在线不等于每台远端机器都能连接，需逐台检测。

              
单机命令ssh_exec
ssh_list_allowed_operations
ssh_run_operation		“查看这台机器的磁盘使用情况。”短命令同步执行；完全访问支持 shell、script、cwd、env；预设模式使用固定操作接口。

              
分组批量ssh_list_groups · ssh_group_cpu
ssh_group_start · ssh_group_status
ssh_group_cancel		group 使用列表返回的完整组名，默认组填「默认分组」。批量执行用 common 共享命令，或 platforms.linux / windows / macos 分别指定；二者选一。默认并行 2 台，最多 4 台；禁用机器跳过，失败逐台报告。

              
长任务ssh_start · ssh_status
ssh_tail · ssh_cancel		构建、安装等任务先取得 runId，再查状态、读取增量日志或取消。MCP 客户端断开后后台任务仍可运行，但本地网关需保持启动。

              
文件传输ssh_upload · ssh_download
ssh_sync		“把本机项目同步到远端，排除 node_modules，先 dryRun。”本机路径指运行网关的电脑。上传、下载支持校验和及续传参数；sync 为本机到远端的单向目录同步，不删除远端多余文件。OpenSSH 使用 SFTP，AccessClient 复用共享 shell；按授权目录执行，用 runId 跟踪。

              
环境与部署预检ssh_target_info
ssh_docker_preflight		“确认机器身份、Docker 状态和剩余磁盘，检查部署端口。”Docker 预检目前需要完全访问权限，只检查，不安装或部署；提供项目名与 create / update / inspect 意图可区分本项目占用。

              
大输出读取ssh_read_output_text
ssh_read_output		输出预览截断时，用返回的 outputRef 分页读取。文本优先使用文本接口；原始接口返回 Base64 数据。

              

              
分组任务返回 groupRunId，每台机器另有 runId。分组协调依赖当前 MCP 进程，完成后的组记录保留 24 小时；MCP 重启会丢失组记录及未派发队列，已派发任务可继续用各自 runId 查询或取消。取消分组后仍需查询最终状态。
