# 运维权限预设（v1）

管理中心的「设置」展示四个内置预设；在机器的「权限管理 → 预设命令组」中勾选并保存后生效。现有机器不会自动切换策略。

| 预设 | 允许范围 |
| --- | --- |
| 基础巡检 | 主机身份、CPU、内存、磁盘、进程摘要和监听端口 |
| 日志排查 | 管理员明确配置的日志文件、服务日志；限制行数，不支持跟随 |
| Docker 只读巡检 | 容器列表、一次性资源统计、健康状态摘要、有限日志 |
| Docker 保护 | 不额外授予操作；明确保持只读保护，拒绝任意脚本、写文件、服务/Docker 修改 |

同一机器可以组合这些预设，允许能力取并集；未选能力默认拒绝。Docker 保护不是关键字黑名单，不允许和完全访问、精确命令白名单混用。当前四组都只提供固定只读操作，因此不勾选 Docker 保护也不会获得修改能力。它用于明确记录保护意图；以后扩展写操作时也必须遵守此约束。

## MCP 使用

先发现该机器实际获准的操作和参数：

```javascript
ssh_list_allowed_operations({"target":"机器别名或不可变 targetId"})
```

然后按返回的参数 schema 调用，例如：

```javascript
ssh_run_operation({"target":"my-server","operation":"system.cpu","parameters":{}})
ssh_run_operation({"target":"my-server","operation":"docker.containers","parameters":{}})
```

日志操作的可选文件/服务由管理中心配置，调用方不能临时扩大范围。Windows、Linux、macOS 使用不同固定命令模板；需要目标系统安装相应查询工具，缺少工具或系统权限时会返回失败，不会自动安装或提权。

`ssh_group_cpu` 对预设机器使用同一个 `system.cpu` 授权入口；未勾选基础巡检的成员单独报告失败。任意 `ssh_exec`、`ssh_start`、组控脚本和 upload/download/sync 对预设机器拒绝执行。连接检测和固定机器身份检查保留，Docker 部署预检仍只供完全访问模式使用。

单次预设操作上限为机器命令上限与 15 秒中的较小值，总输出上限 256 KiB；共用网关执行并发、审计、stdout/stderr 和 outputRef 分页。超过总输出上限会停止执行并报告 output_limit。

## 边界

此策略约束通过本工具发起的操作，不会撤销 SSH 账号在服务器本身的权限，也不会约束其他客户端。生产隔离仍应配合服务器受限账号。只读查询仍有少量资源消耗，日志可能包含业务敏感信息；只开放必要日志资源，不承诺零影响或自动脱敏。

首版内置库不可编辑，机器选择及日志范围可配置。预设未提供安装、重启、删除、容器 exec、任意 shell、环境变量覆盖或文件写入能力。
