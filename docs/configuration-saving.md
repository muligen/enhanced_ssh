# 配置保存

管理中心使用两种保存路径，均保留版本冲突检查和私有文件权限。

- 分组创建、重命名、排序、删除、机器所属分组及说明变更：原子写入 `managed/metadata/<基础版本>.json`，同步更新网关机器目录。不会复制密钥、执行 SSH 校验、替换执行器或关闭持久化会话。
- 未修改任何配置的保存：直接返回当前状态，不创建新版本。
- 删除机器：当剩余机器和共享设置完全不变时，原子保存显式删除记录，增量撤销该机器及旧别名的访问，只关闭被删除机器的独立执行器。保留其他机器的凭证和持久化会话，不重建完整配置。
- 机器别名、连接、密钥、权限、新增机器等变更：创建并校验完整配置版本后再发布。别名目前仍影响生成的 SSH 路由，因此不走元数据路径。

表单未改动连接或权限时，保留服务器返回的原始运行配置，只替换用户编辑的分组／说明，避免界面默认值或隐藏的历史 AccessClient 字段触发一次意外的完整发布。

增量文件绑定基础配置版本，具有独立的并发版本号。V1 只允许分组目录和机器说明／所属分组；V2 额外允许显式的机器删除列表，必须是基础配置中已有机器，不能增加目标或包含账号、地址、密钥、权限变更。连续删除及后续元数据编辑保留累计删除记录。重启时先验证基础配置，再在开放 RPC 前应用删除及元数据，确保已删除机器不会重新出现。完整发布则以当前剩余机器生成新基础版本。保留基础版本的增量文件也随之保留，用于回滚；过期文件随版本清理。

删除仍保留执行中任务互斥、并发版本校验和磁盘发布失败回滚。撤销访问后若独立连接清理失败，保留删除结果并报告清理错误，不恢复已删除机器。

完整保存合并目标凭证目录的权限处理；并发私有文件写入的 Windows ACL 检查按大小合并。每个调用仍检查文件类型、单链接及文件身份，ACL 写入后仍复核，不缓存权限判断。凭证与生成的 SSH 配置各保留一轮必要校验，失败时不切换活动版本。

后台仍使用同步保存响应：页面收到成功时磁盘与当前网关目录均已更新，不把尚未完成的后台任务显示为保存成功。
