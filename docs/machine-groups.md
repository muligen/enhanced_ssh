# 机器分组与 MCP 组控

在左侧机器列表中「新建分组」，再通过机器配置的「机器分组」下拉框选择所属目录，或在列表中直接移动机器。每台机器属于一个组，旧机器自动进入「默认分组」。目录可折叠，搜索时展开匹配的机器。分组、顺序和成员随配置持久化，刷新、重启不会丢失。

组名精确匹配，支持中文，最多 64 字符。组名不是目标别名，也不是权限策略：组内每台机器仍受自己的启用开关、命令白名单和超时限制约束。空组仍然保留。默认分组固定存在，不可删除或改名；其他组可以改名、调整顺序或删除。删除组时，组内机器移回默认分组，不会删除机器或更改其权限。

MCP 的 `ssh_list_groups` 同样包含默认分组与空组。可以使用 `group: "默认分组"` 操作默认目录，空组返回零成员结果。改组名不会改变已经发起的任务快照。

## MCP 接口

| 接口 | 用途 |
| --- | --- |
| `ssh_list_groups` | 列出组名、成员及启用状态 |
| `ssh_group_cpu` | 采样整组 CPU，返回逐台结果和汇总 |
| `ssh_group_start` | 启动整组后台命令，返回 `groupRunId` |
| `ssh_group_status` | 查询整组进度和每台机器的 `runId` |
| `ssh_group_cancel` | 取消尚未开始及正在运行的任务 |

### 查看 A 组 CPU

先将机器的分组设为 `A组`，再让 Codex「查看 A组机器的整体 CPU 占用」。对应调用：

```json
{"group":"A组","concurrency":2}
```

`ssh_group_cpu` 同时给出逐台 CPU 利用率、按机器平均值和按逻辑 CPU 数加权的平均值。失败、停用的机器单独列出，不按 0% 计入平均。采样时间可能略有差异；加权值不代表不同型号 CPU 的实际算力。预设模式通过获准的 `system.cpu` 操作采样，需要勾选基础巡检；其他模式仍需要完全访问权限执行固定采样脚本。

### 给 B 组安装 Docker

让 Codex 先通过 `ssh_list_groups` 确认 B组成员、操作系统与权限，再根据发行版和现有 Docker 状态准备安装命令，用 `ssh_group_start` 发起任务。工具不内置一条适用于所有系统的安装脚本。

同一条跨系统命令可以显式指定 `common`。例如先验证整组主机名：

```json
{"group":"B组","common":{"command":"hostname","timeoutMs":10000},"concurrency":2}
```

不同系统使用 `platforms.linux`、`platforms.windows`、`platforms.macos`，每项支持单行 `command`，或 `shell`、多行 `script`、`cwd`、`env`、`encoding`、`timeoutMs`。只需提供组内实际启用机器所用的系统；缺少必要的系统命令会在启动前报错。不同 Linux 发行版应使用可检测发行版的脚本，或划分为不同组。

组任务快照使用不可变机器 ID。发起后改名、调整组成员不会把已有任务转到另一台机器。查询状态后可对每台 `runId` 使用现有 `ssh_tail` 跟随日志；取消不回滚已经执行的安装或其他操作。

批量执行默认同时运行 2 台，最多 4 台；其余成员排队。`ssh_group_start` 立即返回组句柄，使用 `ssh_group_status` 获取已经派发的每台 `runId`。每台任务独立报告成功、失败、超时或跳过；提交响应丢失时记为未知，保留并发槽位且不自动重试，避免重复安装。其他任务占满网关容量时，相应机器会明确报告容量错误。

## 生命周期

组任务句柄保存在当前 MCP 进程内，最多保留 128 组，完成后保留 24 小时；运行中及结果未知的组不会因超时被淘汰。重启 MCP 会丢失组调度与组句柄，尚未派发的任务不会继续启动；已经启动的机器任务仍可使用保留的 `runId` 查询和取消。长任务期间请保持 MCP 进程运行，定期查询组状态并保存每台任务编号。

升级后，已运行的 MCP 进程需要重新连接，才能加载新的组控工具。
